# 情報設計 (IA)

## URL構造

| パス | 内容 | 種別 |
|---|---|---|
| `/` | 自己紹介を中心にしたポートフォリオトップ | 実装済み・静的コンテンツ |
| `/blog` | 技術記事一覧 | 実装済み・静的サンプルデータ |
| `/blog/$slug` | 技術記事詳細 | 未実装（CMS構築後にデータ駆動化する予定） |
| `/projects` | 制作実績一覧 | 実装済み・GitHub同期データ |
| `/projects/$slug` | 制作実績詳細 | 未実装（CMS構築後にデータ駆動化する予定） |
| `/admin` | 管理画面トップ（ログイン後ダッシュボード） | 未実装（CMS構築時に認証を追加する予定） |
| `/admin/login` | 管理者ログイン | 未実装（CMS構築時に認証を追加する予定） |
| `/admin/articles` | 技術記事のCRUD | 未実装 |
| `/admin/projects` | 制作実績のCRUD | 未実装 |

## ナビゲーション（ヘッダー）

- 技術記事一覧（`/blog`）
- 制作実績一覧（`/projects`）
- 自己紹介（`/` トップページ内のセクションへのアンカーリンク。独立した `/about` は作らない）

## CMS / 静的の切り分け（現状）

- GitHub同期データ: 制作実績（`scripts/sync-github-projects.mjs`）
- 静的（リポジトリ内コンテンツ）: トップページの自己紹介セクション、技術記事のサンプルデータ
- CMSによる技術記事・制作実績の管理は未実装であり、別Issueで構築する

## 公開ページと管理画面の分離（方針）

公開ページはCloudflare Workers上でリクエストごとにSSRする。ビルド時のプリレンダリングは行わない。

- `/admin` 配下は公開コンテンツページのパスと完全に接頭辞を分け、管理画面を構築する際に認証が必要な範囲を明確にする
- 公開ページ（`/`, `/blog`, `/blog/$slug`, `/projects`, `/projects/$slug`）から `/admin` 配下へのリンクは一切張らない
