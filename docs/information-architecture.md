# 情報設計 (IA)

## URL構造

| パス | 内容 | 種別 |
|---|---|---|
| `/` | 自己紹介を中心にしたポートフォリオトップ | 静的 |
| `/blog` | 技術記事一覧 | 静的 |
| `/blog/$slug` | 技術記事詳細 | Firestore駆動 |
| `/projects` | 制作実績一覧 | 静的 |
| `/projects/$slug` | 制作実績詳細 | Firestore駆動 |
| `/admin` | 管理画面トップ（ログイン後ダッシュボード） | 認証必須 |
| `/admin/login` | 管理者ログイン | 認証必須 |
| `/admin/articles` | 技術記事のCRUD | 認証必須 |
| `/admin/projects` | 制作実績のCRUD | 認証必須 |

## ナビゲーション（ヘッダー）

- 技術記事一覧（`/blog`）
- 制作実績一覧（`/projects`）
- 自己紹介（`/` トップページ内のセクションへのアンカーリンク。独立した `/about` は作らない）

## CMS / 静的の切り分け

- Firestore管理（CMS）: 技術記事、制作実績
- 静的（リポジトリ内コンテンツ）: トップページの自己紹介セクション

## 公開ページと管理画面の分離

公開ページはCloudflare Workers上でリクエストごとにSSRする。ビルド時のプリレンダリングは行わない。

- `/admin` 配下は公開コンテンツページのパスと完全に接頭辞を分け、認証が必要な範囲を明確にする
- 公開ページ（`/`, `/blog`, `/blog/$slug`, `/projects`, `/projects/$slug`）から `/admin` 配下へのリンクは一切張らない
